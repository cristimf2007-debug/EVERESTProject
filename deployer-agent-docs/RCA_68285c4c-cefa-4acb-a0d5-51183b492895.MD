# RCA — bioxic-ai: live site missing tracks & videos after deploy

## Problem statement
User reports that on the LIVE site (https://bioxic-ai.emergent.host, www.bioxic.ro) tracks and videos do not appear after a deploy a few minutes ago. In PREVIEW everything is intact: GET /api/tracks = 6, GET /api/videos = 12, ~18 files records. Symptom (verbatim): "UNDE SUNT PIESELE SI VIDEOCLIPURILE... DE CE NU APAR PE SITE".

## Answers to the 4 questions

### 1. Is a deploy running / did it just finish?
It just FINISHED, successfully. Latest run `68285c4c-cefa-4acb-a0d5-51183b492895` (type=redeploy) completed_at 2026-10-24T02:53:15Z with status=success. It is now the active run serving traffic. Nothing is still running. The deploy pipeline is NOT the problem.

### 2. Does production DB contain the data?
Partially — it holds a STALE snapshot, not the current preview content.
Resolved production DB = `bioxic-ai-test_database`.
- tracks: **1** (expected 6)
- files: **7** (expected ~18)
- videos: **collection does not exist** (expected 12)

All 7 file records and the single track were created **2026-10-22** (storage_path values are audio/banners/covers only — NO video paths). The initial deploy ran 2026-10-23T21:22. So production contains exactly the preview snapshot as it existed at the initial-deploy migration — nothing added since.

### 3. Is MONGO_URL/DB_NAME pointing at the expected DB?
Yes. mongo_query resolves MONGO_URL + DB_NAME server-side from the run's secrets and reads `bioxic-ai-test_database`. The platform prefixes the deployment name onto preview's `test_database` → `bioxic-ai-test_database`. This IS the correct production database; the backend is pointed at the right place. The DB is not wrong — it is just under-populated.

### 4. Is the empty/partial DB because the redeploy shipped code-only?
CONFIRMED. Data migration (provision_mongo) runs only on `initial` deploys. The initial deploy (e9b7c81b, 2026-10-23T21:22) migrated preview's state at that moment (1 track, 7 files, 0 videos). Every run since — three redeploys including today's 68285c4c — ships the container image only and does NOT re-migrate data. The 6 tracks / 12 videos / 18 files were created in PREVIEW after the initial deploy, so they were never copied to production. This is not a code bug and not a pipeline failure.

## Root cause
Production MongoDB (`bioxic-ai-test_database`) holds only the initial-deploy snapshot (1 track, 7 files, no videos). Content added in preview after the initial deploy was never migrated because redeploys are code-only. The live frontend therefore renders an almost-empty catalog. The app, the DB connection, and today's deploy are all healthy.

## Suggested fix (user action — data, not code)
The user must get the current data into production. Options:
- Copy preview → production data via the DB Manager (preview DB `test_database` → prod `bioxic-ai-test_database`), OR
- Re-enter the missing tracks/videos through the LIVE admin panel, OR
- Do a Replace-with-fresh-DB deploy so a fresh migration pulls the current preview data.
Note: media binaries already exist in object storage under `bioxic/uploads/...`; only the MongoDB documents (tracks/videos/files) need to be brought over, so a DB copy should restore playback without re-uploading media.
